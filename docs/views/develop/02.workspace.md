# Monorepo 架构规范

> **基于 pnpm workspace 的 Vue 2.6 组件库工程化布局**

## 一、整体架构与角色分工

在本项目中，Monorepo 不仅是代码组织方式，更是 **开发、调试、文档、发布一体化** 的基础设施。各模块职责如下：

| 模块 | 职责 |
|------|------|------|
| **`packages/`** | 存放所有可发布包（UI 组件、工具函数等） |
| **`example/`** | 本地调试沙盒，用于真实环境验证组件 |
| **`docs/`** | 项目文档 |
| **`pnpm-workspace.yaml`** | 定义 workspace 范围，启用软链接依赖解析 |

### 协作流程
```plain
开发者在 packages/ui/button/ 中开发组件
  → pnpm 通过 workspace 协议将 @holyer-lib/ui 链接到 example/node_modules
  → 启动 example 项目 (pnpm dev)
    → 实时验证组件在真实 Vue 2 应用中的行为
  → 修改代码后自动热更新，无需重新构建
```

> ✅ **核心价值**：  
> - **零成本本地联调**：无需 `npm link` 或发布到 registry  
> - **依赖一致性**：所有子包共享根目录的 `vue`、`less` 等依赖  
> - **隔离性保障**：每个包独立 `package.json`，明确边界

## 二、目录结构设计原理

```
holyer-lib/
├── example/                # 本地调试沙盒（Vue 2 项目）
├── docs/                   # 文档
├── packages/
│   ├── ui/                 # 全量 UI 组件库
│   │   └── button/         # 独立组件包（含 package.json）
│   └── utils/              # 工具函数包（纯 JS）
├── pnpm-workspace.yaml     # workspace 范围声明
└── package.json            # 根依赖 + scripts
```

### 为什么必须包含 `example/`？
| 问题 | 解决方案 | 优势 |
|------|----------|------|
| 文档站点（VuePress）缓存干扰 | 创建独立 Vue 2 调试项目 | ✅ 真实运行环境验证✅ 支持复杂交互调试（如路由、状态管理）✅ 避免文档构建副作用 |

> 💡 **启动方式**：
> ```bash
> cd example
> pnpm dev  # 启动本地开发服务器
> ```


## 三、pnpm workspace 配置详解

### 1. 工作区声明
```yaml
# pnpm-workspace.yaml
packages:
  - 'packages/*'   # 所有可发布包
  - 'example'      # 调试项目（虽不发布，但需链接内部包）
  - 'docs'      # 文档
```

> ⚠️ **关键点**：  
> `example` 和 `docs` 必须显式列入，否则 pnpm 无法将其识别为 workspace 成员，导致 `workspace:*` 依赖解析失败。

### 2. 包间依赖管理

#### ✅ 内部依赖：使用 `workspace:` 协议
```json
// example/package.json
{
  "dependencies": {
    "@holyer-lib/ui": "workspace:*",
    "@holyer-lib/utils": "workspace:^0.1.0"
  }
}
```
- `workspace:*`：始终使用本地最新版本（开发期推荐）  
- `workspace:^x.y.z`：锁定兼容版本（适用于稳定包）

#### ✅ 外部依赖：统一提升至根目录
```json
// package.json（根）
{
  "dependencies": {
    "vue": "^2.6.14"        // ← 所有子包共享此版本
  },
  "devDependencies": {
    "less": "^4.5.1",
    "rollup": "^2.79.2"
  }
}
```

> 📌 **依赖提升（Hoisting）机制**：  
> pnpm 默认将公共依赖提升至 `node_modules/.pnpm`，确保：
> - 所有子包使用 **完全相同的 Vue 实例**
> - 避免“多份 Vue 导致组件注册失效”问题

## 四、常见陷阱与解决方案

| 问题 | 根本原因 | 解决方案 |
|------|----------|----------|
| `example` 无法安装 `@holyer-lib/ui` | `pnpm-workspace.yaml` 未包含 `example` | 添加 `'example'` 到 packages 列表 |
| 组件在 `example` 中报错 “Vue not found” | 子包未 external Vue，或依赖未提升 | 1. 确保根目录声明 `vue`2. 检查 `pnpm install` 是否成功 |
| 修改组件后 `example` 未更新 | IDE 缓存或 HMR 失效 | 重启 `pnpm dev` 或清除 `.vite` / `.nuxt` 缓存 |
| `pnpm install` 后依赖缺失 | lockfile 损坏或版本冲突 | 运行 `pnpm install --fix-lockfile` |


## 五、总结

1. **所有可复用代码必须放入 `packages/`**  
   - UI 组件 → `packages/ui/{name}`  
   - 工具函数 → `packages/utils`

2. **`example/` 仅用于调试，不提交业务逻辑**  
   - 保持轻量（仅验证组件 API 和样式）  
   - 不应包含真实项目代码

3. **依赖声明遵循“根集中、子精简”原则**  
   - 公共依赖（Vue/Less）→ 根 `package.json`  
   - 包私有依赖（如 `dayjs`）→ 子包 `package.json`

4. **始终通过 `pnpm install` 初始化**  
   - 禁止使用 `npm` 或 `yarn`，避免 workspace 失效
