# 代码质量规范

> **在 Vue2 生态约束下，构建可靠、无冲突的代码校验体系**

## 一、背景

Vue2 已经停止维护，其配套工具链存在显著兼容性断层：

| 问题 | 影响 | 根本原因 |
|------|------|----------|
| **Vetur 与 Volar 冲突** | VSCode 报错、高亮失效 | 同一工作区无法共存 Vue2/3 插件 |
| **ESLint 与 Prettier 规则重叠** | 自动格式化结果反复震荡 | 两个工具独立运行，规则未对齐 |
| **手动格式化不一致** | 提交包含无关空格变更 | 开发者本地配置差异 |

> ⚠️ **后果**：  
> - 代码审查被噪声干扰  
> - CI 因格式问题失败  
> - 新成员上手成本高


## 二、整体架构与角色分工

为规避上述问题，本项目采用 **“单入口校验”** 策略，将所有质量控制委托给 ESLint：

| 工具 | 职责 |
|------|------|
| **ESLint** | 统一入口：执行代码规范 + 触发格式化 |
| **eslint-plugin-prettier** | 将 Prettier 规则转为 ESLint 规则 |
| **eslint-config-prettier** | 关闭 ESLint 中与 Prettier 冲突的规则 |
| **Husky** | 提交前校验 changeset 存在性 |

### 协作流程
```plain
开发者保存文件
  → VSCode 调用 ESLint（启用 format）
    → eslint-plugin-prettier 执行 Prettier 格式化
    → eslint-config-prettier 屏蔽冗余规则
  → 提交时 Husky 检查 .changeset/*.md 是否存在
    → 若修改 packages/ 但无 changeset，拒绝提交
```

> ✅ **核心优势**：  
> **仅依赖 ESLint 一个工具链**，彻底避免多工具竞争。


## 三、关键配置详解

### 1. 依赖版本锁定
```json
// package.json
{
  "devDependencies": {
    "eslint": "^7.32.0",               // Vue 2 兼容的最新版
    "eslint-plugin-vue": "^8.7.1",     // Vue 2 SFC 支持
    "eslint-plugin-prettier": "^4.0.0",
    "eslint-config-prettier": "^8.3.0" // 关闭冲突规则
  }
}
```

### 2. ESLint 配置
```js
// eslintrc.js
const path = require('path');
module.exports = {
  root: true,
  env: {
    node: true
  },
  extends: ['plugin:vue/essential', 'eslint:recommended', 'plugin:prettier/recommended'],
  parserOptions: {
    parser: '@babel/eslint-parser', // ← 这是给 .vue 和 .js 用的
    // 显式指定 Babel 配置文件的绝对路径，确保 ESLint 能正确加载 Babel 配置
    babelOptions: {
      configFile: path.resolve(__dirname, './babel.config.js')
    }
  },
  rules: {
    'no-console': 'warn',
    'no-debugger': process.env.NODE_ENV === 'production' ? 'error' : 'warn',
    'vue/multi-word-component-names': 'off',
    'vue/no-multiple-template-root': 0,
    'vue/no-mutating-props': 0,
    'vue/no-use-v-if-with-v-for': 0,
    'vue/valid-template-root': 0,
    'no-empty': 0
  }
};

```


## 四、开发者环境配置

### 1. VSCode 设置（必须）
```json
// .vscode/settings.json
{
  // ✅ 启用 ESLint 格式化
  "eslint.format.enable": true,
  // ⚠️ 禁用 Prettier 插件
  "prettier.enable": false,
  // 🔑 关键：关闭直接格式化
  "editor.formatOnSave": false,
  // 🔑 关键：保存时让 ESLint 修复所有问题（含 Prettier）
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  },
  // 指定文件类型使用 ESLint 作为格式化器
  "[vue]": {
    "editor.defaultFormatter": "dbaeumer.vscode-eslint"
  },
  "[javascript]": {
    "editor.defaultFormatter": "dbaeumer.vscode-eslint"
  },
  "[typescript]": {
    "editor.defaultFormatter": "dbaeumer.vscode-eslint"
  },

  // 确保 Prettier 插件尊重项目配置（即使不直接用它）
  "prettier.configPath": ".prettierrc",
  "prettier.requireConfig": true,
  "eslint.validate": ["javascript", "vue"],
  // 关闭 Vetur 的模版类型检查，不修复类型本身。彻底禁用模板插值的 TS 类型检查
  "vetur.experimental.templateInterpolationService": false
}
```

> ✅ **效果**：  
> 保存时自动格式化，且结果与 CI 完全一致。

### 2. 禁止行为
- ❌ 手动运行 `npx prettier --write`  
- ❌ 在 VSCode 中启用 Prettier 插件  
- ❌ 修改 `.prettierrc`（本项目无此文件）


## 五、提交质量守门（Husky）

### 1. Changeset 校验逻辑
```bash
# .husky/pre-commit
#!/bin/sh
node ./scripts/verify-changeset.js
```

### 2. 设计原理
| 场景 | 行为 | 目的 |
|------|------|------|
| 修改 `packages/ui/button` | 必须先 `pnpm changeset` | 确保每次组件变更都有版本日志 |
| 仅修改 `docs/` 或 `example/` | 无需 changeset | 避免非发布变更阻塞提交 |

> 💡 **Changeset 是发布基石**：  
> 它驱动 `pnpm changeset version` 和 `pnpm changeset publish`，实现自动化版本管理和 npm 发布。


## 六、总结

1. **格式化唯一入口**：所有格式化必须通过 ESLint 触发  
2. **VSCode 配置标准化**：团队共享 `.vscode/settings.json`  
3. **提交前自检**：
   ```bash
   pnpm lint          # 检查代码规范
   pnpm changeset add # 若修改了 packages/
   ```
4. **CI 强制兜底**：GitHub Actions 中运行 `pnpm lint`，失败则阻断合并
