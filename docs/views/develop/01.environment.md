# 开发环境


## 一、整体架构与角色分工

在 Vue 2 生态已停止维护的背景下，开发环境的核心目标是 **锁定可工作的工具链组合**，避免因版本漂移导致构建失败。各工具职责如下：

| 工具 | 职责 |
|------|------|
| **Node.js** | JavaScript 运行时基础 |
| **pnpm** | 包管理器 + workspace 管理 |
| **Vue 2 生态工具链** | 构建、文档、测试（Rollup/VuePress/Jest） |

### 协作流程
```plain
开发者使用 Node.js 18.12.0 启动项目
  → pnpm 根据 packageManager 字段自动匹配 10.15.0
  → 构建脚本调用 Rollup 2.79.2 + rollup-plugin-vue 5.1.9
  → 文档站点使用 VuePress 1.8.2（基于 Webpack 4）
  → 所有环节共享根目录的 less@4.5.1
```

> ✅ **核心原则**：  
> **“一次锁定，处处一致”** —— 本地、CI、团队成员环境完全对齐。


## 二、环境要求清单

| 工具 | 版本 | 验证方式 | 说明 |
|------|------|----------|------|
| **Node.js** | `18.12.0` | `node -v` | 与 GitHub Actions CI 环境严格一致 |
| **pnpm** | `10.15.0` | `pnpm -v` | 通过 `package.json#packageManager` 自动启用 |
| **NPM Token** | - | `echo $NPM_TOKEN` | 用于 `changeset publish`，仅需 CI 配置 |

> 💡 **自动校验建议**：  
> 在 `package.json` 中添加：
> ```json
> {
>   "engines": {
>     "node": "18.12.0",
>     "pnpm": "10.15.0"
>   },
>   "packageManager": "pnpm@10.15.0"
> }
> ```


## 三、关键依赖冲突解决方案

### 1. VuePress 兼容性（文档站点）
| 问题 | 解决方案 | 原理 |
|------|----------|------|
| `vuepress@2.x` 仅支持 Vue 3 | 锁定 `vuepress@1.8.2` + `webpack@4.47.0` | VuePress 1.x 是官方维护的 **最后一个 Vue 2 兼容版本** |

```json
// package.json
"devDependencies": {
  "vuepress": "1.8.2",
  "webpack": "4.47.0"
}
```

> ⚠️ **不要升级**：即使出现安全警告，也应优先保证构建可用性。


### 2. Less 工具链一致性
| 问题 | 解决方案 | 效果 |
|------|----------|------|
| `less@<4.5.1` 与 `less-loader@4.1.0` 不兼容 | 使用 `pnpm overrides` 强制提升版本 | 确保所有包使用 **同一 Less 解析器** |

```json
// package.json
"pnpm": {
  "overrides": {
    "less@<4.5.1": "^4.5.1",
    "less-loader@<4.1.0": "^4.1.0"
  }
}
```

> 💡 **为什么有效**？  
> pnpm 的 `overrides` 会覆盖整个依赖树中的指定包，避免子依赖引入旧版。


### 3. Rollup 插件兼容性（组件构建）
| 问题 | 解决方案 | 依据 |
|------|----------|------|
| `rollup-plugin-vue@5.1.9` 仅支持 Rollup 2.x | 锁定 `rollup@^2.79.2` | 官方插件仓库明确声明兼容范围 |

```json
// package.json
"devDependencies": {
  "rollup": "^2.79.2",
  "rollup-plugin-vue": "^5.1.9"
}
```

> ✅ **验证方式**：  
> 运行 `pnpm build:ui` 应无报错，且输出文件包含正确编译的模板和样式。


## 四、常见陷阱与预防措施

| 风险 | 现象 | 预防方案 |
|------|------|----------|
| 本地 Node/pnpm 版本不一致 | 构建成功，但 CI 失败 | 使用 `fnm` 或 `nvm` 管理 Node 版本启用 `packageManager` 字段 |
| 误升级 `vuepress` | 文档站点无法启动 | 将 `vuepress` 版本写死（不使用 `^`） |
| 忽略 `overrides` | 样式编译报错 | 提交前运行 `pnpm why less` 确认版本 |


## 五、总结

1. **拒绝模糊版本**：所有关键依赖使用 **固定版本或窄范围**（如 `1.8.2` 而非 `^1.8.0`）  
2. **CI/CD 对齐本地**：GitHub Actions 使用 `actions/setup-node@v4` 指定 Node 18.12.0  
3. **升级前必验证**：  
   - 本地构建 (`pnpm build`)  
   - 文档启动 (`pnpm docs:dev`)  
   - 测试通过 (`pnpm test`)  
4. **安全警告处理**：  
   - 低危漏洞：忽略（Vue 2 项目无法彻底修复）  
   - 高危漏洞：评估是否影响构建/运行，再决定是否降级或打补丁
