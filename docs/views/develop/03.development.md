# 开发流程

> **说明：**
> 
> 目前仅 ui 和 utils 支持 rollup 打包，directives和style未打包，后续根据实际情况进行打包配置

## 一、整体架构与角色分工

在本组件库中，以下三个核心模块协同完成 **按需引入** 与 **全量引入** 的双重目标：

| 模块 | 职责 | 类比 |
|------|------|------|
| **独立组件包** | 每个组件作为独立 npm 包发布（如 `@holyer-lib/ui/button`） | “标准化零件” |
| **全量 UI 入口** | 聚合所有组件，提供统一安装接口（`@holyer-lib/ui`） | “整机装配说明书” |
| **Rollup 构建系统** | 编译 `.vue` 文件，输出 ESM/CJS/UMD 三种格式 | “多语言翻译工厂” |

### 协作流程
```plain
开发者创建 packages/ui/button/
  → 配置 button/package.json（声明包名）
  → 编写 button/index.js（导出组件）
  → 构建脚本遍历目录，调用 Rollup 打包
    → 输出 dist/button.esm.js 等
  → 用户可直接 import '@holyer-lib/ui/button'
  → 同时，ui/index.js 手动聚合所有组件
    → 支持 import { HiButton } from '@holyer-lib/ui'
```

> ✅ **重要提示**：  
>
> + 所有组件必须位于 `packages/ui/` 下  
> + 包名格式固定为 `@holyer-lib/ui/{component}`  
> + **不要** 将组件放在 `packages/` 根目录（如 `packages/button`）


## 二、UI 组件开发流程

### 1. 创建组件目录
```bash
# 在 packages/ui/ 下新建组件
mkdir packages/ui/button
```

### 2. 配置独立包（仅用于 npm 元信息）
```json
// packages/ui/button/package.json
{
  "name": "@holyer-lib/button",
  "version": "0.1.0",
  "main": "dist/button.cjs.js",     // ← 仅用于 npm 元信息，非构建依据
  "module": "dist/button.esm.js",   // ← 实际输出路径由 Rollup 脚本控制
  "unpkg": "dist/button.umd.js"
}
```

> 💡 **说明**：  
> `main`/`module` 字段 **不影响构建行为**，仅用于 npm 发布后工具（如 Webpack）自动解析入口。实际输出路径由 `scripts/build.js` 中的 `dist/${name}.${format}.js` 决定。

### 3. 编写组件入口
```js
// packages/ui/button/index.js
import HiButton from './src/index.vue';
export default HiButton;
```

### 4. 手动注册到全量入口
```js
// packages/ui/index.js
import HiButton from './button';
import HiTitle from './title';

const components = [HiButton, HiTitle];

const install = function (Vue) {
  components.forEach(component => {
    Vue.component(component.name, component);
  });
};

export { HiButton, HiTitle };
export default { install, HiButton, HiTitle };
```

> ⚠️ **注意**：  
> - 所有新组件必须在此文件中 **显式 import 并导出**  
> - `components` 数组中的变量必须在 `import` 中声明


## 三、Rollup 打包策略详解

### 1. 两种打包模式

#### ✅ 独立组件打包（按需引入）
- **触发条件**：目录包含 `package.json`
- **入口文件**：`{component}/index.js`
- **输出文件**：
  - `dist/{name}.esm.js`（ES Module）
  - `dist/{name}.cjs.js`（CommonJS）
  - `dist/{name}.umd.js`（UMD）
- **用户用法**：
  ```js
  import HiButton from '@holyer-lib/button'; 
  ```

#### ✅ 全量 UI 打包（整体引入）
- **入口文件**：`packages/ui/index.js`
- **输出文件**：`dist/ui.esm.js` 等
- **用户用法**：
  ```js
  import { HiButton, HiTitle } from '@holyer-lib/ui';
  ```

> ✅ **构建顺序**：先打包所有独立组件，再打包全量 UI

### 2. 关键配置特点

| 配置项 | 说明 | 示例 |
|--------|------|------|
| **插件链** | `rollup-plugin-vue` + `rollup-plugin-less` | 样式通过 `insert: true` 内联注入 |
| **外部依赖** | `external: ['vue']` | 避免将 Vue 打包进组件，减小体积 |
| **输出格式** | ESM / CJS / UMD 三格式并存 | 满足现代构建工具、Node、浏览器需求 |
| **UMD 命名** | 基于组件目录名转换（如 `button` → `Button`） | 全局变量 `window.Button` 可访问 |

> 📌 **命名规则**：  
> 组件文件必须以 `Hi` 开头（如 `HiButton.vue`），确保全局注册名唯一。


## 四、当前限制与优化方向

| 问题 | 根本原因 | 解决方案 |
|------|----------|----------|
| **一个目录仅支持一个默认导出** | 构建脚本从 `package.json` 读取单一名字 | 改为解析 `index.js` 的 `export` 语句 |
| **样式无法按需加载** | Less 样式内联注入 DOM | 可选：生成独立 `.css` 文件 |


## 五、打包策略反思

### 为什么必须使用独立组件包？
| 需求 | 方案 | 结论 |
|------|------|------|
| 支持 `import HiTitle from '@holyer-lib/title'` | **独立 package.json + 目录结构** | ✅ 必要（Vue 2 无 Babel 按需方案） |
| 减少维护成本 | 全量包 + `babel-plugin-import` | ❌ Vue 2 生态不支持可靠实现 |

> 💡 **经验总结**：  
> 当前方案在 **组件数量 < 5 时** 是最优解。若未来组件膨胀，建议：
> 1. 保留全量包（兼容老用户）
> 2. **暂不** 追求 CSS 按需加载（优先级低）

## 六、总结

1. **命名规范**：组件文件以 `Hi` 开头（`HiButton.vue`），目录名小写（`button`）
2. **路径准确**：按需引入路径为 `@holyer-lib/ui/{dir}`，**不是** `@holyer-lib/{dir}`
3. **手动注册**：新增组件后，务必更新 `packages/ui/index.js`
4. **避免重复打包**：确保 `external: ['vue']` 生效
5. **样式内联接受**：Vue 2 组件库通常体积小，内联样式可接受
