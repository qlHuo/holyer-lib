# 测试方案

**基于 **`@vue/test-utils`** + **`jest** **`**+ **`@vue/vue2-jest`**（适用于 Vue 2.6 + pnpm monorepo）**

## 一、整体架构与角色分工
在 Vue 2 组件库的测试体系中，以下三个工具协同工作：

| 工具 | 职责 | 类比 |
| --- | --- | --- |
| **Jest** | 测试框架：提供测试组织、断言、覆盖率、执行环境等能力 | “考试系统” |
| **@vue/test-utils (v1)** | Vue 2 专用测试工具库：提供组件渲染、DOM 查询、事件触发等 API | “实验台 + 显微镜” |
| **@vue/vue2-jest** | Jest 的 `.vue` 文件预处理器：将单文件组件（SFC）编译为 JavaScript 模块 | “翻译官” |


### 协作流程
```plain
Jest 运行 test/*.spec.js
  → 遇到 import Component from './Component.vue'
  → 调用 @vue/vue2-jest 将 .vue 编译为 JS
  → @vue/test-utils 使用 mount() 渲染该组件
  → Jest 通过 expect() 断言 DOM 行为是否符合预期
```

> ✅ **重要提示**：  
>
> + Vue 2 必须使用 `@vue/test-utils`** v1**（Vue 3 使用 v2，API 不兼容）  
> + **不要使用 **`vue-jest@4`，它与 Jest 27+ 存在兼容性问题；应使用官方维护的 `@vue/vue2-jest`
>



## 二、Jest：测试框架核心语法
### 1. 基础结构
```javascript
describe('HiTitle.vue', () => {          // 测试套件（Test Suite）
  it('renders correctly with default props', () => {  // 测试用例（Test Case）
    expect(wrapper.text()).toBe('Hello');             // 断言（Assertion）
  });
});
```

### 2. 常用断言（Matchers）
| 断言 | 说明 | 示例 |
| --- | --- | --- |
| `.toBe(value)` | 严格相等（`Object.is`） | `expect(a).toBe(b)` |
| `.toEqual(value)` | 深度相等（对象/数组） | `expect(obj1).toEqual(obj2)` |
| `.toContain(string)` | 字符串包含 | `expect('hello').toContain('ell')` |
| `.toMatch(regex)` | 正则匹配 | `expect(style).toMatch(/rgb$255, 0, 0$/)` |
| `.toBeCloseTo(number, digits)` | 浮点近似 | `expect(0.1 + 0.2).toBeCloseTo(0.3, 5)` |
| `.toThrow()` | 函数抛错 | `expect(() => fn()).toThrow()` |


### 3. 生命周期钩子（可选）
```javascript
beforeEach(() => { /* 每个测试前运行 */ });
afterEach(() => { /* 每个测试后清理 */ });
```

> 💡 Vue 组件测试通常无需手动清理（Jest 自动重置 DOM），除非有全局副作用。
>



## 三、@vue/test-utils (v1)：Vue 2 测试工具详解
### 1. 渲染组件
#### ✅ `shallowMount(component, options)`
+ **浅渲染**：仅渲染当前组件，**子组件被 stub（替换为空壳）**
+ **推荐用于大多数测试**：速度快、隔离性好

```javascript
import { shallowMount } from '@vue/test-utils';
const wrapper = shallowMount(HiTitle, {
  propsData: { content: 'Hello' }
});
```

#### ✅ `mount(component, options)`
+ **完整渲染**：递归渲染所有子组件
+ **用于测试动态组件、插槽透传、父子交互**

```javascript
const wrapper = mount(Parent, {
  propsData: { childComponent: MyIcon }
});
```

> 📌 **最佳实践**：  
>
> + 默认用 `shallowMount`  
> + 仅当需要验证子组件真实渲染时（如 `<component :is="prefixIcon" />`）才用 `mount`
>



### 2. 测试配置项（`options`）
| 选项 | 用途 | 示例 |
| --- | --- | --- |
| `propsData` | 传入 props | `{ size: 'large', color: '#ff0000' }` |
| `slots` | 注入插槽内容（字符串或 VNode） | `{ default: '<p>Text</p>', prefix: '<span>★</span>' }` |
| `attrs` | 模拟 `$attrs`（绑定到根元素） | `{ 'data-test': 'title', id: 'my-id' }` |
| `stubs` | 控制子组件 stub 行为 | `{ Child: false }`（不禁用 stub） |
| `mocks` | 模拟全局属性 | `{ $route: mockRoute }` |




### 3. Wrapper API：操作与断言
`wrapper` 是组件实例的封装，提供以下常用方法：

| 方法 | 说明 | 示例 |
| --- | --- | --- |
| `find(selector)` | 查找单个 DOM 元素 | `wrapper.find('.hi-title__text')` |
| `findAll(selector)` | 查找多个元素 | `wrapper.findAll('li')` |
| `text()` | 获取文本内容 | `expect(wrapper.text()).toBe('Hello')` |
| `classes()` | 获取 class 列表（数组） | `expect(wrapper.classes()).toContain('active')` |
| `attributes()` | 获取 attributes | `expect(wrapper.attributes('id')).toBe('my-id')` |
| `exists()` | 判断元素是否存在 | `expect(wrapper.find('.icon').exists()).toBe(true)` |
| `trigger(event)` | 触发 DOM 事件 | `wrapper.find('button').trigger('click')` |
| `setProps(props)` | 动态更新 props（异步） | `await wrapper.setProps({ size: 'small' })` |


> ✅ **黄金法则**：  
**优先通过 DOM 输出（文本、class、属性）进行断言，避免直接访问 **`wrapper.vm`**（耦合实现细节）**
>



## 四、@vue/vue2-jest：Vue 文件预处理器
### 1. 作用
+ 将 `.vue` 单文件组件（SFC）编译为普通 JavaScript 模块
+ 处理 `<template>`、`<script>`、`<style>`，提取导出对象
+ 供 Jest 和 `@vue/test-utils` 使用

### 2. 配置方式（`jest.config.js`）
```javascript
// jest.config.js
module.exports = {
  testEnvironment: 'jsdom',
  moduleFileExtensions: ['js', 'vue'],
  transform: {
    '^.+\\.js$': 'babel-jest',
    '^.+\\.vue$': '@vue/vue2-jest' // ← 关键配置！
  },
  testMatch: ['<rootDir>/test/**/*.spec.js']
};
```

### 3. 为什么必须用 `@vue/vue2-jest`？
+ `vue-jest@4` 未适配 Jest 27+ 的 transformer API 变更
+ 会导致错误：`TypeError: Cannot destructure property 'config' of 'undefined'`
+ `@vue/vue2-jest` 是 **Vue 官方维护的修复版**，兼容 Jest 27/28/29



## 五、典型测试文件示例
```javascript
// test/title/title.spec.js
import { shallowMount, mount } from '@vue/test-utils';
import HiTitle from '../../packages/ui/title/src/HiTitle.vue';

describe('HiTitle.vue', () => {
  // 测试默认渲染
  it('renders correctly with default props', () => {
    const wrapper = shallowMount(HiTitle, {
      propsData: { content: 'Hello Title' }
    });
    expect(wrapper.find('.hi-title__text').text()).toBe('Hello Title');
  });

  // 测试动态组件（必须用 mount）
  it('renders prefixIcon component when provided', () => {
    const MockIcon = { render: h => h('svg', { class: 'mock-icon' }) };
    const wrapper = mount(HiTitle, {
      propsData: { prefixIcon: MockIcon }
    });
    expect(wrapper.find('.mock-icon').exists()).toBe(true);
  });

  // 处理浮点精度
  it('applies correct bar height', () => {
    const wrapper = shallowMount(HiTitle, { propsData: { size: 'large' } });
    const style = wrapper.find('.hi-title__bar').attributes('style');
    const height = parseFloat(style.match(/height:\s*([\d.]+)px/)[1]);
    expect(height).toBeCloseTo(21.6, 1); // 允许 1 位小数误差
  });

  // 处理颜色标准化
  it('applies custom text color', () => {
    const wrapper = shallowMount(HiTitle, {
      propsData: { color: '#ff0000' }
    });
    const style = wrapper.find('.hi-title__text').attributes('style');
    expect(style).toMatch(/color:\s*rgb$255,\s*0,\s*0$/);
  });
});
```



## 六、常见问题与解决方案
| 问题 | 根本原因 | 解决方案 |
| --- | --- | --- |
| `Cannot find module 'core-js/...'` | Babel 预设自动注入 polyfill | 安装 `pnpm add -D core-js@3` |
| `prefixIcon` 未渲染 | `shallowMount` stub 了动态组件 | 改用 `mount` |
| 断言 `21.6px` 失败 | JS 浮点运算精度误差 | 用 `toBeCloseTo()` 或正则提取数值 |
| 颜色 `#ff0000` 变成 `rgb(...)` | JSDOM 自动标准化颜色值 | 用正则匹配 `rgb(255, 0, 0)` |
| `Cannot destructure property 'config'` | 使用了不兼容的 `vue-jest@4` | 替换为 `@vue/vue2-jest` |

## 八、总结
1. **隔离测试**：优先使用 `shallowMount`，减少外部依赖
2. **覆盖边界**：测试默认值、极端值、空值、插槽优先级
3. **验证行为而非实现**：通过 DOM 输出断言，避免访问 `vm`
4. **处理环境差异**：用正则/近似断言应对 JSDOM 格式化和浮点误差
5. **保持测试独立**：每个 `it` 应可单独运行，无顺序依赖
